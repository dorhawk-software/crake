OpenVPN 3 left a connection running. OpenVPN 3 can lose track of a session's process: the session ends, the process doesn't, and it keeps reconnecting on its own, changing the other tunnels' DNS each time (every name went to one company for a moment; Firefox hung). Crake already notices it (a minute after the session went) and says so in the log and a notification. This puts it in the panel, where it stays until it's dealt with. The process is OpenVPN 3's (its own user), so the app can't stop it; craked can, with a wider permission. Two ways:
A. Say how, with the command to copy (chosen)
Nothing new is allowed. The command ends it at once (-9: these processes hang, and a plain kill didn't stop the ones seen). "Got it" hides it; it goes by itself once the process has ended. "Got it" no longer takes a line of its own: two places for it.
A1. On the title's line, where "Stop it" was in B and "Restart" is in the update notice.

B. Stop it from the panel (not chosen: Crake shouldn't end another program's process)
One click: craked ends the process, and logs it. Before it does, craked checks the number is still OpenVPN 3's session process (its program and its start time, as the app saw it) and nothing else.

The trade-off. A needs nothing new, but asks for a terminal and sudo. B is one click, but craked's AppArmor profile, which today lets it signal only its own processes (openconnect), would have to allow ending processes outside it:
  • craked would check the program is /usr/libexec/openvpn3-linux/openvpn3-service-client and the start time is the one the app saw, so a wrong or reused number stops nothing;
  • but it can't see whose session it was: the app sees only your sessions, so on a computer shared with another user, it trusts your app that the session ended (polkit asks as for any change);
  • Fedora and the other systems without AppArmor need no rule; macOS and Windows don't run OpenVPN 3 sessions.
Either way the log and the notification stay as they are.
