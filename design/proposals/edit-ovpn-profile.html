Editing an OpenVPN 3 profile, in Crake (for experts). Changing one value of a profile (a remote, a route, a dhcp-option) means exporting it, editing the file and importing it again: "too many clicks", and slow when debugging a config. openvpn3 can't edit a profile in place; Crake can do the round trip: show the profile's text, let it be changed, then give openvpn3 the new text under the same name, remove the old one, and reconnect. Out of the way of people who just import IT's file: it's reached from the tunnel's details only.

2. The profile's text
A window of its own: the text as openvpn3 holds it, line numbers, plain monospace editing. The certificates and keys inside (<ca>, <cert>, <key>, <tls-crypt>, …) are folded into one line each and kept exactly as they are: no one edits base64 by hand, and it keeps them off the screen. Changed lines are tinted. Save is there once something changed.

4. A profile openvpn3 won't show
Whoever imported it can lock it (openvpn3's locked_down, often IT's profiles): then no one, Crake included, can read its text. The fact says so instead of offering Edit.
Initech's profile is locked in OpenVPN 3: its text can't be shown or changed here.
How it works
  • The round trip: openvpn3's Fetch gives the text; Save imports the new text (persistent, the user's, as Import .ovpn… does), and only once that's accepted removes the old profile. The new one has the same name, so Crake's tunnel keeps pointing at it. A connected tunnel reconnects on the new profile.
  • Kept as they were: the folded certificates and keys go back byte for byte. Overrides and tags set with openvpn3 config-manage are copied to the new profile where openvpn3 lets the owner read them.
  • Not offered: for profiles of another user (shared with you), sealed ones (openvpn3 refuses changes), and IT's managed tunnels in Crake.
